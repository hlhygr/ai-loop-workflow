# Loop 策略

本文件是审查通过条件、复核、额外终审及 Reviewer 路由的规范来源。何时启动独立审查见 [任务路由](task-routing.md)；授权与证据边界见 [核心入口](../SKILL.md#权限与证据)，同时遵循宿主指令和适用工作区规则。

## 通过条件

从首次审查起允许两种结果：

- `clean`：当前范围未发现确定问题。
- `accepted_non_blocking`：所有遗留问题均不阻塞主流程、不造成严重影响且不是 P0；逐项公开证据、影响和接受理由。

P0、主流程阻塞、严重影响，以及影响成功标准的验证缺口、未解决业务决策或授权阻塞不能包装成通过。严重度与阻塞性分别判断，P1 特别核实影响；包括 P2 在内的非阻塞遗留可从首轮接受，不要求零 finding。用户要求继续修复时按已有范围执行。审查通过不授予合并、提交、推送或外部操作权限。

## 范围与复核

- 首次完整审查使用全新上下文，明确对象、基线、目标、可判定的通过标准及排除项；聚焦当前改动和直接影响，不开放式穷举。
- 高风险任务提高首次独立审查的覆盖和验证深度，检查最终实现、关键失败路径、实际依赖与消费端。不能用增加 Reviewer 数量代替缺失的运行证据；高风险本身不强制第二轮。
- 首次审查已经覆盖最终产物、证据充分且之后无重要变化时直接交付。同一 finding 在原目标与契约内的窄修复，由原 Reviewer 定向复核并结合验证证据关闭。
- 审查后新增行为、数据流、公共契约、直接影响范围或风险，前次未覆盖最终产物，或存在需要独立补足的关键审查证据时，使用全新 Reviewer 补充审查；用户明确要求额外终审时同样执行。记录具体触发原因和需补足的范围，称为 final，不机械重查无关部分。final 通过后结束；若随后再次实质改变审查对象，原通过结论不自动覆盖新增变化。
- 人工或工作区新增改动按语义判断：无关改动保留并排除；影响共享契约、调用链或已有验证时才扩围。定向复核发现有证据的新问题，或原 Reviewer 不可用时，按实际影响使用全新 Reviewer，不为复用上下文长期等待。

同一问题反复修改、修复互相抵消或持续没有新证据时，汇总改动、验证与反证，重新检查根因、契约和复现条件，再决定最小修复。不按固定轮次自动放行、追加审查或询问用户；范围外优化不进入修复循环。

## 角色与报告

Reviewer 只读取证、返回确定问题和最小建议；主 Agent 核实 findings，并在已有修复授权内继续实施、验证与必要复核。用户只要求审查时以报告交付。

首次说明范围与基线，后续只报告新增、关闭、接受或未关闭的问题及证据变化；不统计审查轮次或调用总数。结论保留全部未解决项、接受理由和验证缺口，不把带遗留通过写成已修复。已有 plan 时证据放 findings、执行与验证放 progress；下一步只维护 task_plan。没有 plan 的局部审查直接在回复中报告，不为登记审查新建计划。

## Reviewer 路由与生命周期

独立 Reviewer 使用未包含实施过程的新上下文，使用宿主当前配置；工作流不选择或切换模型。由宿主适配器创建上下文并返回可追踪的 Reviewer 标识；原 finding 的定向复核尽量复用原 Reviewer。没有此能力时明确独立审查未完成，可提供自查或供用户转交的审查材料，但不能以此冒充独立通过。

提供用户原始请求、审查对象、基线、目标与通过标准、排除项、相关路径、验证证据和只读约束，不灌输候选根因或预期 finding。Reviewer 自行核对输入，不把提供的路径视为完整范围。在交接中明确任务为“独立审查”或“定向复核”；被委派的 Reviewer 直接取证，不递归派生。定向复核仅核对原 findings 与直接副作用；具体调用和角色标记由适配器处理。

超时不表示完成。替换前核对原 Agent 是否仍运行或已有结果，不并行启动运行中 Agent 的替代者、不超出宿主容量；不能确认状态时仅暂停依赖替换的部分。无法创建独立 Agent 时说明独立审查未完成，不以主 Agent 自审冒充。常规任务不额外预检槽位或维护 Agent 台账。

当前目标完成、风险相称验证有证据、必要审查通过且无影响成功标准的阻塞，即可交付。恢复入口与安全重放见 [planning](../../planning/SKILL.md)，不在此复制计划生命周期。
