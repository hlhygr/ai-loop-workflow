# 技能发现与任务路由

## 发现用户领域技能

领域技能由用户或宿主管理；AI Loop 不要求特定名称、目录、格式改造或“扩展注册”，不负责安装和版本管理。

优先使用当前会话已有的技能/工具目录。仅需名称、描述、入口与可见的前置条件；先据此选择，再读取完整说明。缺少目录时，使用宿主已提供的能力查询或用户指定目录；目录为空不意味着可以自行下载技能或扫描其他账号/个人文件。

- 用户明确指定技能时优先核对该技能；不存在或不可访问时说明缺口，不假装已调用。
- 按目标、输入输出、权限和实际可用工具匹配，不能只凭名称或关键词。多个候选等价时选择足以完成目标的最小能力；只有会改变业务结果、范围或外部状态的差异才需要用户决定。
- 一个领域技能足以完成结果时直接使用。多个技能存在真实阶段依赖时，只加载当前阶段所需内容；后续需要时再加载。互相矛盾的说明以宿主指令、用户要求和适用工作区约束裁决，不能让技能扩大授权。
- 没有匹配领域技能时，利用现有通用能力完成可验证部分；缺必要条件时明确说明并询问或报告阻塞。不能虚构工具、登录态、独立 Reviewer 或成功结果。

用户技能的实际内容按其原入口读取，不复制进工作流；工作流的领域检查清单不替代用户技能。

## 使用核心技能

- 局部且可定向验证的任务：直接处理或调用所需领域技能，不加载 planning 和审查全文。
- 有阶段依赖、跨仓库协调、复杂排障或跨会话恢复：按需加载同仓库 planning，复用目标对应状态。工具次数、资料来源和可机械拆分步骤数不单独触发。
- 用户要求审查，或改动涉及关键共享契约、高影响数据、权限、安全或复杂回归：进入独立证据审查；纯分析和耗时长本身不强制 Reviewer。
- 风险决定验证深度；新增证据改变依赖或范围时重新分诊。符合独立、只读及当前范围要求的既有审查可复用，复核和通过条件见 [Loop 策略](loop-strategy.md)。
