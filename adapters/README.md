# 宿主接入契约

接入的是同一套 AI Loop。宿主将 [统一入口](../skills/dispatch-ai-loop-workflow/SKILL.md) 加入项目指令、会话指令或技能发现目录，用户之后直接描述目标。载入入口后按其分诊持续执行；用户不需要选择执行模式。

## 宿主提供什么

- 当前可用的技能/工具目录：名称、描述、入口和可见前置条件即可；需要时读取选中说明。优先复用宿主机制，不要求用户领域技能改造格式或注册为工作流扩展。
- 实际能力：读写文件、执行命令、外部服务、创建独立上下文、生命周期事件。只提供实际可用能力，目录不授予调用权限。
- 工作区/计划根目录，以及可选的不透明会话标识。不能提供可靠标识时用显式计划 ID，不能共享“最近计划”。
- 用户和工作区的权限限制与约定；不得通过加载技能扩大权限。

## 独立审查

具备此能力的宿主创建不含实施过程的新上下文，传递原始目标、对象/基线、成功标准、约束和证据，不传预期 finding；返回结果和可用于定向复核的标识。自查不算独立审查，缺少能力时说明缺口。模型配置由宿主控制，适配器不硬编码模型名称。

## 状态与事件

文件工具可以直接维护三文件；Python 工具和生命周期事件均为可选增强。事件映射与计划 CLI 见 [接口](../skills/planning/references/cli.md)。接入层负责把归一化数据转换成宿主真正支持的格式，不把某宿主的成功当作其他宿主已验收。

纯对话环境可由用户提供入口及必要的引用内容；仅使用现有上下文完成分诊和分析，不声称能自动读取未提供文件、执行工具或持久化状态。需要能力而当前没有时应明确报告，不削弱完成标准。

已有参考接入：[Codex](codex/README.md)。其他宿主可以依据此契约接入，无需更改核心规则；未实测的接入不标为已支持。
